# Decisions

## D1-D9 (short form)

- **D1:** Fix jobs only; every job has `vulnerable_ref` and `patched_ref`. A new finding without an upstream fix uses an owner-supplied reference patch labeled "reference fix (not upstream)".
- **D2:** Own small mutator (stdlib `ast`) mutating only top-level functions that differ between the two refs; no mutmut. Implemented in M4 as `grader/mutate.py` with seed `0`, at most 8 mutants, and a `0.8` kill threshold.
- **D3 (superseded):** The runtime runs as the owner with no separate OS user, no privileged wrappers, and no password-gated approval. The owner is trusted; the LLM is the adversary; the barrier is information asymmetry plus the broker's fixed tool boundary. The store is owner-readable at `0700`.
- **D4:** Owner writes variants; a separate session may draft, owner reviews; fixture variants by the builder; no adversary agent in v1.
- **D5:** Platform-neutral integration through a dedicated MCP tool surface. Adapted in Nyxowl: one Nyxowl MCP server exposes `nyx_testwriter_*` and brokers the locally installed wrappers; no second `tw-tools` server.
- **D6:** Lock file generated with pip-tools in a throwaway build-only venv; runtime venv contains only pytest, hypothesis, and pinned transitive dependencies.
- **D7:** Eval targets are wheels-only in per-item hash-pinned venvs; the target is never installed.
- **D8:** Python 3.12 for the grader and sandbox runtime.
- **D9:** Bubblewrap + resource limits. Adapted: limits are applied inside the sandbox by `_limits.py` because a pre-bwrap `RLIMIT_NPROC` prevents namespace creation on this machine.

## Rootless runtime (supersedes D3)

| Decision | Reason |
| --- | --- |
| The runtime, store, workspace, and venv live under `$HOME/.nyxowl/test-writer` and `$HOME/tw-jobs`; every wrapper runs as the owner. | The owner's requirement is a rootless install: no root, no service account, no privileged wrappers, and no password prompt. |
| There is no separate grader OS user. The owner is trusted, the LLM is the adversary, and the barrier is information asymmetry plus the fixed broker/tool boundary. | A same-user process cannot gain a privilege boundary from another same-user process; pretending otherwise adds install risk without adding isolation. |
| The store is owner-readable at `0700`. The subagent still cannot read it because the subagent has no host filesystem tools. | Store confidentiality was never the barrier against the LLM; the barrier is that the subagent sees only the job inputs and fixed broker responses. |
| The target-collusion residual remains owner-reviewed. | The harness and an owner-supplied target share one interpreter; the owner reviews both refs before accepting `PROVEN`. A separate-process judge is M6/out of scope. |

## M0 decisions

| Decision | Reason |
| --- | --- |
| The source lives in the Nyxowl repository at `test-writer/`. | Owner decision: one reviewable tree and one merge path. |
| Resource limits are applied inside the sandbox by `_limits.py`, not by `prlimit` before bwrap. | A pre-bwrap `RLIMIT_NPROC` makes bwrap fail namespace creation on this machine with `Resource temporarily unavailable`. |
| Install, store, workspace, tmp, and venv paths are resolved at call time from `TW_*` overrides, with defaults under the owner's home. | Tests may set the environment after import, and the default install never requires a system path. |
| The agent is registered in `agents/subagents/` as part of M0.5, not M6. | Registration is a reviewed source change; M6 verifies host isolation at runtime. |
| `requirements.lock` is generated by the owner's bootstrap script. | The agent must not install packages, reach the network, or invent unverified hashes. |
| M0 uses the Python 3.12 standard library only. | The sandbox and its tests must run before the runtime venv exists. |

## M3 decisions

| Decision | Reason |
| --- | --- |
| Gates 1-3 are lint, the vulnerable snapshot, and the patched snapshot. M4 adds gates 4-6 for flake, hidden variants, and mutation; numbers above 6 are refused with `GATE_UNAVAILABLE`. | The runtime now has evidence for all six quality checks. |
| The owner draft lives under `~/tw-jobs/<id>/`. Approval bundles exactly `meta.json`, `manifest.json`, `src-vulnerable.tar`, and `src-patched.tar` and sends them directly to the local `tw-store-job`; the store verifies and atomically installs the job. | The draft is reviewable without touching the private store, and the store only accepts a verified bundle. No privilege transition is needed. |
| `python_path=[]` means the repository root. | Small repositories and root-level modules must not need a synthetic package directory. |
| Subagent feedback is marker-free and aliased; the real reason stays in the private store, status, and report. | The broker never forwards canary, variant, mutant, stdout, or stderr markers. |
| No new receipt kind, no second MCP server, no new dependencies, and no TypeScript changes. | M3 reuses the existing broker and receipt path and stays inside the Python runtime tree. |
| Proof tests may not request `request`, `pytestconfig`, `monkeypatch`, or `mocker`; lint rejects them and the harness fails the setup phase if one is declared. | The builtin `request` fixture exposes `config.pluginmanager.get_plugin("plugin")`, which can mutate the harness module globals and force a false PROVEN. A runtime guard is required even though lint normally catches the same shape. |
| The harness binds a truthy detector condition to the target's observed return when the job sets `unsafe_return_contains`. | A condition alone could be fabricated after branching on source bytes; the marker forces the test to obtain the unsafe value from the target in the same test. |
| Test code may not read `/work/src`, `/work/harness`, or installed grader code. Import machinery and target code may read `/work/src` only outside the test phase (collection/import); during setup, call, and teardown every frame, including target frames, is untrusted and blocked by `sensitive_read`. | The snapshot is read-only input to the target, not an oracle for the test; a target-supplied frame must not become a read channel once the test is running. |
| The harness signs every report with HMAC-SHA256 over a canonical JSON encoding using a per-run key delivered through `TWP_REPORT_KEY`; the parent requires a valid 64-hex MAC. | `/work/out` is test-writable, so report shape alone cannot distinguish an authentic report from a forged one. The plugin removes the key from `os.environ` before importing the test or target. |
| A valid report must also agree with the real bwrap exit status: `pytest_exit` equals the process exit code, `passed` requires exit 0, `failed` requires non-zero, and `error` kinds are checked against their expected exits. | A forged `passed` document could otherwise survive a failing pytest run. Reports with a missing/invalid MAC or inconsistent exit are `report_error="invalid"` and classify as setup/no-report, never PROVEN. |
| Lint rejects `pytest.exit` as `PYTEST_HOOK` and `SystemExit`/`KeyboardInterrupt`/`GeneratorExit` names as `DYNAMIC_ESCAPE`. | A lint-clean test must not be able to terminate pytest with a chosen exit status after writing a forged report. |
| A `PROVEN` verdict is not a hostile-target claim. The target snapshot is owner-supplied; before accepting `PROVEN` the owner reviews both approved refs for plugin-state access (`sys.modules["plugin"]`/plugin attributes), writes outside the snapshot at import/collection, and `os._exit`/`os.abort`, and records the reviewed ref hashes with the job. | The harness and target share one interpreter, so a malicious snapshot can forge harness state. A separate-process judge is out of scope for M3 and deferred; the owner review is the compensating control for this residual. |

## M4 decisions

| Decision | Reason |
| --- | --- |
| Gate 2 (vulnerable) and gate 3 (patched) use fixed hash seed `0`; gate 4 re-runs both snapshots with fixed seeds `1` and `2`. The canary stays per-run random. | A fixed seed makes the primary evidence reproducible; the extra seeds expose tests that branch on `hash()` or other seeded state without leaking a canary. |
| Gate 4 compares the seed-1/2 classifications with the seed-0 result. Any mismatch is `FLAKY` and therefore `UNPROVEN`; safety and setup observations keep their real reason. | A proof test must be stable before it can be evidence; a single inconsistent run is enough to reject it. |
| Gate 2 accepts a vulnerable-snapshot failure when the signed report says `outcome=failed` and the failure type is `AssertionError` or pytest `Failed`; it does not require detector attribution. A target exception remains `SETUP_ERROR_VULN:wrong_exception:<Type>`, and a vulnerable pass remains `NO_DETECTOR_HIT_ON_VULN`/`UNPROVEN`. | The verdict must rest on observable behaviour. Detector globals live in the same interpreter as the untrusted proof test, so they are evidence, not a trustworthy pass condition. |
| Gate 4 requires real assertion/pytest failures on the vulnerable snapshot and passes on the patched snapshot under seeds 1/2, without attribution. Gate 5 requires a real failure on the still-vulnerable variant and a pass on the fixed-differently variant, without attribution. | The same behavioural rule applies to all differential checks; hidden variants and mutation provide the strength evidence once the basic differential is real. |
| Gate 5 requires both hidden variants, refuses a missing one with `VARIANT_MISSING`, and checks a still-vulnerable and a fixed-differently snapshot. | A test that only works for the exact patched implementation is weak; the hidden variants test both directions without exposing their refs or tars to the subagent. |
| Byte-identical variant tars are `VARIANT_MISLABELED`; a test that passes on the still-vulnerable variant, or fails there with a target exception, is `VARIANT_TOO_WEAK`; a test that fails on the fixed-differently variant is `VARIANT_OVERFIT`. | These labels describe the three distinct quality failures and route to different owner actions. |
| Gate 6 mutates changed top-level functions with an in-tree `ast` mutator, never imports the target, and samples at most 8 mutants with seed `0`. The score is `killed / ran` and the threshold is `0.8`. | The mutator stays stdlib-only and deterministic, and the threshold ensures the test distinguishes more than one narrow implementation detail. |
| Mutation scoring counts `failed` as killed, `passed` as survived, and `setup`/`error` as invalid/skipped. A run with no valid mutant is `NA` and does not fail the job. | A mutant that cannot execute is not evidence either way; refusing a job because its fixture generated no valid mutants would be a false negative. |
| Mutant and variant source, refs, and raw output stay out of feedback and `--inputs`; reports expose counts, scores, and survivor IDs only. | The subagent must not be able to fit to the hidden checks or read the target implementation. |
| `detector_seen`, `detector_attributed`, and `detector_calls` stay in reports and counts as evidence only. No gate reads them as a pass condition. | A malicious in-process test can introspect the plugin module and forge those values; making them load-bearing would turn a forgeable global into a security boundary. |
| Lint bans interpreter-introspection attribute names as `DYNAMIC_ESCAPE` for every expression root: `os`, `inspect`, `_settings`, `_sys`, `currentframe`, `getframe`, `tb`, `tb_next`, `tb_frame`, `tb_lineno`, `f_globals`, `f_locals`, `f_back`, `f_code`, `gi_frame`, `cr_frame`, and `co_consts`. | This raises the bar for the obvious report-forging gadgets (for example `pkg.codec.os.environ` and `hypothesis._settings.inspect`) without banning legitimate `pytest.raises`, `detector.check`, target calls, `exc.value`, or `tmp_path` I/O. It is defense in depth; it does not make an in-process test hostile-code-proof because a determined test can still reach the same interpreter. |
| The proof test runs as untrusted quality code inside bwrap. The verdict trust model is behavioural: vulnerable fails with a real assertion, patched passes, hidden variants behave as labelled, and mutants are killed. The test is untrusted for quality, not treated as a hostile-code security boundary. A malicious test or an owner-supplied target can introspect the same interpreter (frames, plugin globals, `pkg.codec.os`) and forge reports. The owner reviews the test and spec; a separate-process judge remains future work. | The product goal is to reject weak LLM tests, not to make an in-process test hostile-code-proof. The lint hardening closes the documented gadgets but does not change the underlying trust boundary. |
| The target-collusion owner review remains in force for M4. | Mutation and variants add quality evidence but do not create a separate-process judge, so the shared-interpreter residual is unchanged. |

## M5 decisions

| Decision | Reason |
| --- | --- |
| A terminal gate run writes `test.py`, `proof.json`, `chain.log`, and `REPORT.md`; `report.md`/`report.json` remain for compatibility. | M5 needs a frozen, independently verifiable evidence record without changing the existing broker or status contract. |
| Canonical JSON is `sort_keys=True`, `ensure_ascii=True`, `separators=(",", ":")`, and `proofHash = sha256(canonical(body))` over every field except `proofHash` and `chain`. | One deterministic encoding makes the self-hash reproducible in any stdlib interpreter and across installs. |
| Runtime hashes cover the effective files actually executed: `gate/*.py`, `grader/**/*.py`, `grader/harness/pytest.ini`, and `bin/*`, excluding `__pycache__`/`*.pyc`. Frozen hashes cover `meta.json`, `manifest.json`, both source tars, optional variant tars, and `test.py`. | The recheck must detect drift in exactly the code and inputs that produced the verdict, not unrelated repository files. |
| `chain.log` is append-only, per-job, JSON-lines; each entry commits to its predecessor and `entryHash`; the proof anchors `{head,length}`. | Hash linking plus a proof-held anchor makes truncation, editing, deletion, and reordering below the anchor evident without a keyed secret. |
| `chain.log` is refused when it is a symlink, exceeds 8 MiB, or exceeds 10,000 entries; appends use `O_NOFOLLOW` and a zero-byte write is fatal. | A symlinked log would let recheck follow an attacker-chosen file, and an unbounded tail is a read/parse DoS; the caps never constrain a normal proof-plus-recheck history. |
| Recheck verifies proof -> runtime -> frozen inputs -> chain -> state, then re-runs the gate pipeline and compares derived evidence. It appends one chain entry only on match or a post-run mismatch. | Refusing a failed artifact and never writing state/report/proof/test keeps replay auditable and fail-closed. |
| Evidence comparison covers verdict, reason, flags, gates, mutation score/killed/ran/survivors, variant statuses, and flake runs, and never includes raw output. | Raw output is sensitive and detector state is not a pass condition; the verdict rests on recomputed behaviour and aggregate quality counts. |
| Recheck also compares the full `counts.vulnerable`, `counts.patched`, and `counts.violations` blocks, normalizing an absent block to `{}`. | The vulnerable and patched gate blocks are recomputable evidence; including them catches drift the aggregate gates line would hide, while early terminals without `patched` still compare equal. |
| `proof.json` and `REPORT.md` never include target/test/variant/mutant source, raw sandbox output, or a canary; `REPORT.md` may include owner-only commit refs. | The owner needs provenance, while the proof artifact must stay safe to retain and share. |
| `tw-recheck` exits `0` on a recomputed match, `1` on mismatch or refusal, `2` on usage, and `78` when the runtime is absent. | A single stable exit contract lets the owner and automation distinguish a real replay from a missing runtime. |

## M6 decisions

| Decision | Reason |
| --- | --- |
| A finish call after a terminal verdict writes an advisory `finish.json` (`0600`) and returns `advisoryFlags`; it never mutates state, proof, chain, `test.py`, or `REPORT.md`. | Advisory flags such as `INJECTION_SUSPECTED` are useful owner context but must not change a verdict or move a proof hash. Keeping them in a separate record lets `tw-recheck` stay green. |
| `tw-status` reads the advisory record, accepts only the two allowed strings, deduplicates, caps the list at 8, and returns `[]` when the record is missing or invalid. | Status is a broker/owner read path; it must never forward free-form or oversized data from an owner-writable file. |
| M6 evidence is model-free: `m6_threerun.py` repeats the four fixture verdicts three times and `m6_parent_e2e.mjs` drives the real stdio MCP flow. J4's advisory flag is labelled scripted plumbing evidence, not model judgment. | The repository can prove plumbing and regression stability without claiming an LLM behavior result. |
| A live OpenCode host-isolation transcript is a manual verifier step and is never fabricated. | Running a model host is outside the rootless runtime evidence and needs the verifier's environment. |
| The broker forwards only the five `TW_*` runtime overrides to spawned wrappers and keeps the rest of the host environment stripped. | A temporary install/store/workspace must be honoured by the wrapper scripts as well as by the MCP process; credentials and unrelated host state stay out of the child environment. |
| The subagent boundary is three-layer. Config denies `read`, `edit`, `glob`, `grep`, `shell`, `webfetch`, `websearch`, `subagent`, `skill`, `question`, `external_directory`, `experimental_image_generate`, and `execute`, then a broad `nyxowl_*` deny, then allows exactly the five Test-Writer tools. It emits no wildcard `{"action":"*",...}` deny and does not deny `opencode_list_mcp_resources` / `opencode_read_mcp_resource`. The generated plugin hook then enforces a local five-action allowlist for `nyx-testwriter` and fails closed for that agent if it throws. A third layer, `ctx.session.hook("context", restrictTools)`, applies a two-phase filter to the per-request `event.tools` snapshot for `nyx-testwriter`. Before the MCP tools register, the live snapshot contains only native host tools, so the filter deletes only `opencode_models`, `opencode_session_move`, `opencode_session_rename`, `opencode_worktree_create`, and `opencode_worktree_list`, preserving the rest so MCP registration is not suppressed. Once any allowed Test-Writer tool appears (suffix match `testwriter_job|write|lint|gate|finish`, prefixed or bare, plus wrapped entries), the filter keeps only allowed entries and removes every other key or array element. Both object and array snapshots use the same phased allowlist/denylist fallback; the filter is a no-op for other agents or a missing snapshot and swallows its own errors. Partially privileged agents keep the narrower rule set and fail-open behavior. | Live QA showed a wildcard deny and either OpenCode resource-listing deny all remove the five allowed `nyx_testwriter_*` tools from the model's tool surface. Config alone therefore cannot deny the resource-listing actions while keeping the MCP tools exposed, and a config deny for `opencode_models` hides them too. The permission hook plus the per-request snapshot filter close that gap, including for future host actions, without a config deny. Live re-verification of the three-layer boundary with the two-phase filter is pending. |
