# Decisions

## D1-D9 (short form)

- **D1:** Fix jobs only; every job has `vulnerable_ref` and `patched_ref`. A new finding without an upstream fix uses an owner-supplied reference patch labeled "reference fix (not upstream)".
- **D2:** Own small mutator (stdlib `ast`) mutating only Python lines changed between the two refs; no mutmut.
- **D3:** Grader runs as separate OS user `tw-grader`; data crosses only through root-owned wrappers via `sudo -u tw-grader`; approval requires the owner's password.
- **D4:** Owner writes variants; a separate session may draft, owner reviews; fixture variants by the builder; no adversary agent in v1.
- **D5:** Platform-neutral integration through a dedicated MCP tool surface. Adapted in Nyxowl: one Nyxowl MCP server exposes `nyx_testwriter_*` and brokers the root-owned wrappers; no second `tw-tools` server.
- **D6:** Lock file generated with pip-tools in a throwaway build-only venv; runtime venv contains only pytest, hypothesis, and pinned transitive dependencies.
- **D7:** Eval targets are wheels-only in per-item hash-pinned venvs; the target is never installed.
- **D8:** Python 3.12 for the grader and sandbox runtime.
- **D9:** Bubblewrap + resource limits. Adapted: limits are applied inside the sandbox by `_limits.py` because a pre-bwrap `RLIMIT_NPROC` prevents namespace creation on this machine.

## D10-D14

| ID | Decision | Reason |
| --- | --- | --- |
| D10 | One Nyxowl MCP server exposes the `nyx_testwriter_*` tools; there is no second `tw-tools` stdio server. | One broker, one install path, and one place to enforce fail-closed behaviour. |
| D11 | No new receipt kind is added. The proof is evidence attached to the PR and to a promoted `security` Blackboard entry. | Reuses the existing verify/seam/slop/exploit gate instead of inventing a parallel trust path. |
| D12 | The subagent has no host read/edit/write/shell/webfetch tools; it gets only five dedicated Test-Writer tools. | The job inputs are the whole trust boundary. |
| D13 | Proof tests are not added to the target's normal test discovery. | The proof needs the grader-only `detector` fixture and the target's pytest cannot run it. |
| D14 | v1 is Python-only; the primary checks DNA before prepare and non-Python targets return `NA`. | No silent fallback to an unsupported stack. |

## M0 decisions

| Decision | Reason |
| --- | --- |
| The source lives in the Nyxowl repository at `test-writer/`. | Owner decision: one reviewable tree and one merge path. |
| Resource limits are applied inside the sandbox by `_limits.py`, not by `prlimit` before bwrap. | A pre-bwrap `RLIMIT_NPROC` makes bwrap fail namespace creation on this machine with `Resource temporarily unavailable`. |
| `TW_INSTALL_ROOT`, `TW_STORE_ROOT`, and `TW_TMP_ROOT` overrides exist for rootless tests. | Tests must not require `/opt/test-writer` or `/var/lib/test-writer`; production keeps those defaults. |
| The agent is registered in `agents/subagents/` as part of M0.5, not M6. | Registration is a reviewed source change; M6 verifies host isolation at runtime. |
| `requirements.lock` is generated by the owner's bootstrap script. | The agent must not install packages, reach the network, or invent unverified hashes. |
| M0 uses the Python 3.12 standard library only. | The sandbox and its tests must run before the runtime venv exists. |

## M3 decisions

| Decision | Reason |
| --- | --- |
| Gates 1-3 are lint, the vulnerable snapshot, and the patched snapshot; gate numbers above 3 are refused with `GATE_UNAVAILABLE` until M4. | The runtime only has evidence for these three checks; a later milestone adds variant and mutation gates. |
| The owner draft lives under `~/tw-jobs/<id>/`. Approval bundles exactly `meta.json`, `manifest.json`, `src-vulnerable.tar`, and `src-patched.tar` and sends them to `tw-grader` through password sudo; `tw-store-job` verifies and atomically installs the job. | The draft is reviewable without touching the private store, and the store only accepts a verified bundle. |
| `python_path=[]` means the repository root. | Small repositories and root-level modules must not need a synthetic package directory. |
| Subagent feedback is marker-free and aliased; the real reason stays in the private store, status, and report. | The broker never forwards canary, variant, mutant, stdout, or stderr markers. |
| No new receipt kind, no second MCP server, no new dependencies, and no TypeScript changes. | M3 reuses the existing broker and receipt path and stays inside the Python runtime tree. |
| Proof tests may not request `request`, `pytestconfig`, `monkeypatch`, or `mocker`; lint rejects them and the harness fails the setup phase if one is declared. | The builtin `request` fixture exposes `config.pluginmanager.get_plugin("plugin")`, which can mutate the harness module globals and force a false PROVEN. A runtime guard is required even though lint normally catches the same shape. |
| The harness binds a truthy detector condition to the target's observed return when the job sets `unsafe_return_contains`. | A condition alone could be fabricated after branching on source bytes; the marker forces the test to obtain the unsafe value from the target in the same test. |
| Test code may not read `/work/src`, `/work/harness`, or installed grader code. Import machinery and target code may read `/work/src` only outside the test phase (collection/import); during setup, call, and teardown every frame, including target frames, is untrusted and blocked by `sensitive_read`. | The snapshot is read-only input to the target, not an oracle for the test; a target-supplied frame must not become a read channel once the test is running. |
| The harness signs every report with HMAC-SHA256 over a canonical JSON encoding using a per-run key delivered through `TWP_REPORT_KEY`; the parent requires a valid 64-hex MAC. | `/work/out` is test-writable, so report shape alone cannot distinguish an authentic report from a forged one. The plugin removes the key from `os.environ` before importing the test or target. |
| A valid report must also agree with the real bwrap exit status: `pytest_exit` equals the process exit code, `passed` requires exit 0, `failed` requires non-zero, and `error` kinds are checked against their expected exits. | A forged `passed` document could otherwise survive a failing pytest run. Reports with a missing/invalid MAC or inconsistent exit are `report_error="invalid"` and classify as setup/no-report, never PROVEN. |
| Lint rejects `pytest.exit` as `PYTEST_HOOK` and `SystemExit`/`KeyboardInterrupt`/`GeneratorExit` names as `DYNAMIC_ESCAPE`. | A lint-clean test must not be able to terminate pytest with a chosen exit status after writing a forged report. |
| A `PROVEN` verdict is not a hostile-target claim. The target snapshot is owner-supplied; before accepting `PROVEN` the owner reviews both approved refs for plugin-state access (`sys.modules["plugin"]`/plugin attributes), writes outside the snapshot at import/collection, and `os._exit`/`os.abort`, and records the reviewed ref hashes with the job. | The harness and target share one interpreter, so a malicious snapshot can forge harness state. A separate-process judge is out of scope for M3 and deferred; the owner review is the compensating control for this residual. |
